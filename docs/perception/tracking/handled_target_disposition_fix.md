# 定位失败后误排除目标：修复说明

原始诊断及首次验证基于 `merge` 的 `a29c2d2`；交付前已接入最新 `2160940`，
保留其中的 60 秒保护配置、人脸阈值及日志改动。三人场景中，A 核验通过后，B/C 若分别定位失败，
原实现会在恢复巡逻时依次把三个 ID 全部加入已处理名单，导致全绿、没有主目标。

## 行为变更

在 `MissionState` 中增加 `uint32 handled_target_id`，总控明确提供业务处理结果，
感知不再从上一任务阶段推断结果。

| 结束条件 | `handled_target_id` | 返回巡逻时 |
|---|---|---|
| `VERIFY_IDENTITY` 接受 `AUTHORIZED` | 当前目标 ID | 排除该目标 |
| `TRACK_INTRUDER` 接受最终 `TARGET_LOST` | 当前目标 ID | 保留原有跟踪结束后的排除 |
| 位置确认超时 | 0 | 目标保持可选 |
| 确认/接近/核验阶段丢失 | 0 | 目标恢复可见后仍可选 |
| 执行错误，包括持续跟踪中的技术错误 | 0 | 不授予业务处理豁免 |

结果保留在 `RECOVER_PATROL` 和随后的 `PATROL` 快照中。感知即使漏收中间状态，
也能用当前巡逻快照排除正确的人。开始下一目标或重置总控会话时清零。
恢复阶段的执行错误被忽略、恢复 watchdog 超时，都不会覆盖已确定的业务结果。

感知只在进入新的巡逻状态序号时应用结果。同序号心跳不得重置离场计时，也不得把
已到期的排除项重新加入。ROS adapter 拒绝同序号但结果不一致的快照、越界 ID、
阶段不合法或恢复目标与处理结果 ID 不匹配的消息。

`target.handled_ignore_absence_sec` 保留最新 `merge` 的 60 秒默认值及连续离场语义，
并将原有默认阈值测试同步到 59/60 秒边界。定位失败后的恢复/重试流程保留：修复不保证雷达融合会
成功，也未新增失败冷却或公平轮询策略。若最大框始终定位失败，它仍可能被重复尝试；
这应另行通过定位诊断或有界重试调度处理，不能把未核验的人误标为已处理。

## 验证场景

- A 被明确处理后，B/C 仍可选；B/C 确认失败不能累计为全部排除。
- 单独出现 VERIFY、TRACK、RECOVER 阶段不构成已处理证据。
- 只收到返回巡逻的快照，也能正确应用 A 的结果。
- 重复巡逻心跳不延长 60 秒连续离场阈值；已到期项不会被同一快照重新添加。
- 成功结果经过恢复错误/超时后仍保留，新任务及会话重置清零。
- 错误来源、目标、状态序号的事件不能产生成功处理结果。
- 新字段经过 ROS 消息发布/订阅后，感知仍选择未处理的人。

新回归测试在旧主目标实现上失败，在修复实现上通过。WSL 使用可移植核心构建，
没有运行 TensorRT、相机、雷达、导航运动，也没有进行实机验收。

## 部署与回退

这是 ROS 消息接口扩展，不能只复制 `primary_target_manager.cpp` 或只替换 tracking
可执行文件。应在集成工作区统一重建 `dog_patrol_interfaces` 及所有依赖
`MissionState` 的总控、导航、感知、控制台等节点，并统一重启。旧接口生成物和新节点
不可混用。不要把 WSL 的 `TRACKING_ENABLE_ORIN_RUNTIME=OFF` 测试构建当作 Orin
生产运行构建。

在部署前保留现有版本和实际生效参数。回退也应整套恢复接口与相关节点，不能只回退
其中一端。已运行旧实现的进程应重启，避免旧内存排除名单残留。

使用控制台启动时，先退出整个 `robot_console/app.py`；仅点击停止导航/感知节点
会留下常驻任务管理器。重建后从新终端加载新工作区的 `install/setup.bash`，用
`ros2 interface show dog_patrol_interfaces/msg/MissionState` 确认新字段存在，并用
`ros2 pkg prefix` 分别确认接口、总控和感知包来自该工作区，再启动控制台。
回退遵循同样顺序：全停、切换整套旧环境、重新加载、再启动。

实机验收前开始记录 `/mission/state`、`/mission/event`、`/rosout` 和带 `id/raw` 的
感知预览，按以下条件判断：

1. A 授权后的恢复和巡逻快照应带 A 的 `handled_target_id`；B/C 仍有主目标资格。
2. B/C 分别被接受为目标后，确认其定位失败原因及
   `CONFIRM_TARGET → RECOVER_PATROL → PATROL` 的 `state_seq`、`target_id` 和
   `handled_target_id`；返回巡逻时处理结果应为 0，失败对象应可再次成为红框。
   仅凭框色无法确认失败是否走过预期路径。
3. 若 B 一直是最大框，它可能反复被选中；需让 B 暂时离开或调整位置，使 C 也被
   选中并单独验收，不能将 C 没有获得选择机会误判为补丁失效。
4. 对已处理的 A 分别测试连续离场不足 60 秒返回、连续离场超过 60 秒后返回。
   记录语义 `id`，确认观察的是同一身份；若语义 ID 已重新分配，应另查重识别问题。
